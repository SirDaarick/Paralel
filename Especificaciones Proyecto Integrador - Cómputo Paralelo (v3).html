🔍 Descripción del problema

El estudiante deberá seleccionar un problema computacionalmente intensivo, paralelizable por datos o por tareas, perteneciente a un área afín a la inteligencia artificial (ej. multiplicación de matrices densas para redes neuronales, convoluciones 2D, optimización por enjambre de partículas, clustering k-means en alta dimensión, o simulación de epidemias con autómatas celulares). El problema debe resolverse mediante al menos tres enfoques distintos: versión secuencial (baseline), versión paralela con API de memoria compartida (OpenMP, pthreads) y versión paralela con API de paso de mensajes o aceleradores (MPI, CUDA, OpenCL, o Python multiprocessing + NumPy). Se debe documentar cada paso del diseño usando el Método de Foster.

🧮 Análisis del problema · Estimación de operaciones

Realice un análisis de complejidad teórica, contando el número total de operaciones aritméticas/lógicas en función del tamaño de entrada n. Importante: "Operaciones" se refiere a operaciones escalares (sumas, multiplicaciones). No confundir con FLOPS (operaciones por segundo).

📐 Fórmula general de operaciones (ejemplo para multiplicación de matrices C = A × B de NxN):
Total de multiplicaciones = N³, total de sumas = N³ - N², total de operaciones ≈ 2N³ - N².
Para N = 2048: Operaciones totales ≈ 2·(2048³) - 2048² ≈ 1.72 × 10¹⁰ operaciones escalares.

📊 Caso de estudio 1: Hardware conocido → estimación de tiempos (ejemplo ilustrativo)

⚙️ Hardware especificado:

  • CPU: AMD Ryzen 7 5800X (8 núcleos / 16 hilos, 3.8 GHz base)
  • RAM: 32 GB DDR4
  • GPU opcional: NVIDIA RTX 3060 (3584 núcleos CUDA)

Estimación secuencial: T_seq = (total operaciones) / (rendimiento sostenido en operaciones/segundo). Suponiendo 20 × 10⁹ ops/seg (20 Gops) → T_seq ≈ 1.72e10 / 2e10 = 0.86 s.
Estimación paralela (OpenMP, 8 hilos): speedup ideal 8, con overhead ~6.5 → T_par ≈ 0.86 / 6.5 ≈ 0.132 s.
Estimación paralela (GPU, CUDA): speedup potencial >100, limitado por transferencias → estimado 0.015 s.

⚠️ Estos números son un ejemplo. El estudiante debe realizar sus propios cálculos basados en su problema y hardware real o supuesto.

⏳ Caso de estudio 2: Plazo fijo → hardware necesario (ejemplo ilustrativo)

🗓️ Restricción temporal:

El problema debe resolverse en ≤ 0.5 segundos. Tamaño del problema: N = 4096 (matriz 4096x4096, operaciones ≈ 1.37e11).
Rendimiento requerido: 1.37e11 ops / 0.5 s = 2.74e11 ops/s (274 Gops).
Con eficiencia 70% → pico ≥ 391 Gops.
Hardware sugerido: 2x CPU Intel Xeon (32 núcleos), o GPU NVIDIA RTX 4070, o cluster de 4 nodos con MPI.

📏 Análisis de escalamiento (strong & weak scaling)

Evalúe el tiempo de ejecución al escalar el problema y el hardware simultáneamente para mantener el tiempo constante (escalamiento débil). Use la función de isoeficiencia para determinar cómo crece el tamaño del problema con respecto al número de procesadores a fin de mantener eficiencia fija.

🔧 Escalamiento fuerte: tamaño fijo, variar núcleos.
📏 Escalamiento débil: duplicar núcleos, duplicar tamaño.

Curva de isoeficiencia para algoritmo paralelo (multiplicación de matrices por bloques). Eje X: número de procesadores (log), eje Y: tamaño del problema (N). Líneas para eficiencia constante del 80%.
🐍 Código Python (matplotlib): 
import matplotlib.pyplot as plt
import numpy as np
p = np.array([1,2,4,8,16,32])
N_80 = 500 * p**1.2  # función de isoeficiencia ejemplo
plt.figure(figsize=(8,5))
plt.loglog(p, N_80, 'bo-', linewidth=2, markersize=8)
plt.xlabel('Número de procesadores (p)', fontsize=12)
plt.ylabel('Tamaño del problema (N)', fontsize=12)
plt.title('Función de Isoeficiencia (Eficiencia = 80%)', fontsize=14)
plt.grid(True, alpha=0.3)
plt.savefig('figura5.jpg', dpi=150, bbox_inches='tight')
